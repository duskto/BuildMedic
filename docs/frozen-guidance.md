# 冻结开发指导对照

实验协议 `4.0` 在完整分组对照上增加显式、只读的开发指导。用户在登记前选择最多五个已发布经验版本，服务端一次性复制指导文案、来源链和训练用量。三个修复组获得完全相同的指导，日志组仍只读固定日志。

本功能用于固定训练输入，尚未测量真实模型的迁移收益。来源和分区均是 20 项公开构造任务；不能据此称为严格盲测或真实仓库泛化。原有 1.0 / 2.0 / 3.0 实验、报告与复算口径继续保留。

## 页面使用

1. 先对登记开发案例运行普通自适应诊断，主动开启原有“使用同域经验并整理任务反思”。例如首页的分页案例属于开发分区。来源补丁通过最终独立验证后，显式发布经验。
2. 在“策略对比”的实验组别中选择“冻结开发指导 · 开发分区四组”或“冻结开发指导 · 测试分区四组”。页面只列当前会话、策略兼容且来源链全部来自开发案例的已发布版本。
3. 明确勾选版本，最多五个。顺序按请求中的版本 ID 顺序保留，不自动改用最新条目。也可不选，登记冻结空指导作为对照。
4. 登记后查看指导指纹、来源版本、来源模型和单独列出的训练用量；点击运行才会请求模型。每个分区仍为 10 个案例 × 四组，重复次数和修复预算固定。

登记与复制在同一个 owner 事务锁内执行。后续发布、撤销或库内容变化不会改写已有实验的输入。撤销后的版本不能被新实验选为直接输入；已经形成的历史来源链保留其事实，仍需全部通过开发来源校验。

## 输入与公平性

| 组别 | 冻结指导 | 运行方式 |
| --- | --- | --- |
| A 日志解释 | 不接收指导 | 固定日志，无源码、工具或 Runner |
| B 单次固定策略 | 相同指导文案 | 固定策略，独立验证 |
| C 独立多次策略 | 相同指导文案，每次从同一输入开始 | 不共享尝试之间的反馈 |
| D Harness² | 相同指导文案，诊断和策略优化上下文均可读取 | 原生 4 次诊断、3 次策略提议 |

只复制已发布经验的 cue、lesson、edits 供模型参考，不向模型提供训练补丁、旧证据 ID、来源任务 ID、私有标签或完整训练策略。原始领域、版本、来源任务、内容指纹和来源模型保留在审计快照中。新任务的诊断仍必须引用当前任务的真实证据，指导不能作为已验证根因。

普通任务的原生同域 `Library` 功能保持原样。4.0 实验采用共享指导文案作为单独的实验条件，不启用在线反思、经验自动累积或新的发布草稿；不会改写基础策略、只读记忆或 guardrails。当前模式不会只向 D 组额外提供训练材料。

可以比较 4.0 空指导与 4.0 已选指导，两者都需要真实重复运行。不要把 3.0 的历史记录当成同一输入条件直接合并，也不要用脚本模型的通过结果声称指导有效。

## 来源校验与成本

直接输入必须是同一会话的 active 版本，具有当前兼容的策略 profile 和固定 Harness² SHA。每个来源任务及祖先都必须属于完整数据清单的开发案例，源码指纹一致，已完成修复，并保留对应选中补丁的最终独立验证。显式标为测试分区的来源被拒绝；测试案例、跨会话来源、不兼容版本、循环、缺失节点或超过 50 个来源节点的链均不能登记。

快照上限为 75 KB。全部祖先来源按唯一任务去重统计训练模型调用和已知 Token，用量缺失另计；任何来源费用未知时，总费用保持 `null`。空指导确实没有训练来源，训练计数和费用均为零。

训练消耗独立展示，不重复加入当前分区每个修复任务的调用账本。现有配对分析继续分析当前修复过程，4.0 使用独立 scope 标识；完整研究需要同时报告快照中的训练消耗，不能只比较推理阶段费用。

## 接口与离线复算

`GET /api/v1/evaluation/guidance-versions` 返回当前会话可选的开发版本，最多检查最近 30 个 active 版本。不执行模型，也不返回其他会话的记录。

创建仍使用 `POST /api/v1/experiments` 和 Idempotency-Key。在完整 3.0 分区计划上改用以下字段即可：

```json
{
  "schema_version": "4.0",
  "guidance_version_ids": []
}
```

以上仅为覆盖字段，仍须保留完整分组计划、案例、预算等字段。空列表明确表示空指导；非空列表使用已发布版本的 32 位 ID，不接收客户端指导文案、内容指纹或自定义路径。

例如生成不使用已发布经验的控制计划，不请求模型：

```sh
uv run --extra adaptive python - <<'PY'
import json
from pathlib import Path
plan = json.loads(Path('evaluation/grouped-test.json').read_text())
plan.update(schema_version='4.0', name='frozen-guidance-empty-control', guidance_version_ids=[])
output = Path('var/acceptance/frozen-guidance-test.json')
output.parent.mkdir(parents=True, exist_ok=True)
output.write_text(json.dumps(plan, ensure_ascii=False, indent=2) + '\n')
PY
# 后续运行会产生真实模型用量，需已启动 API / Worker / Runner。
uv run --extra adaptive python scripts/run_evaluation.py \
  --plan var/acceptance/frozen-guidance-test.json \
  --state var/acceptance/frozen-guidance-test-session.json
```

服务端在登记时冻结完整 `frozen_guidance`。三个修复任务的快照包含相同内容和 `experiment_binding.guidance_sha256`；日志任务只绑定指纹。导出报告包含冻结内容、来源链、训练用量和输入校验依据，离线复算不读取当前经验库、源码或网络。

4.0 沿用分组行为评分 2.0 和独立诊断审核。签名回执绑定完整公开报告 SHA，因此也绑定指导条件。诊断审核单不额外暴露指导版本、来源链或训练费用。此功能使用已有 JSON 存储，不新增数据库迁移。

## 本轮验证

后端覆盖版本顺序、空指导、来源链去重、测试来源 / 测试绑定 / 跨会话 / 撤销 / 不兼容 / 源码漂移 / 循环拒绝，任务和报告篡改拒绝，登记后发布与撤销不改写输入，以及评分和审核兼容性。

原生 Harness² 集成使用明确的 HTTP 模型替身与真实 pytest 子进程：先生成并发布开发经验，再验证日志组、单次、多次和自适应四种路径；三个修复组的指导投影逐项相同，三个原生策略上下文均包含冻结指纹，未发起反思或共享库更新。工具循环另验证指导不进入源码与日志证据索引。浏览器覆盖选择、空对照、来源链接、训练费用未知和移动布局。

这些是协议与执行链路验收，没有新增真实模型成绩或人工诊断标签；真实收益评估仍待运行。
