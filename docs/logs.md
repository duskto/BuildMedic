# 长日志证据与按行阅读

长日志曾只把末尾片段交给模型，可能遗漏前面的失败原因。现在 GitHub 日志诊断、修复组的目标 / 回归基线，以及固定策略的验证失败反馈，会优先选择失败上下文，同时保留开始和结束信息。原始下载仍在现有大小、重定向和脱敏规则内进行。

## 原始行号与失败索引

完整日志先脱敏再保存为任务产物。索引中的 SHA256、总字节数和行数都对应这份完整脱敏内容，不对应网络下载的原始秘密或节选后的文本。

索引识别 Python traceback、常见异常、pytest 失败、依赖错误和 CI 错误标记；能读取 GitHub 日志行首的 UTC 时间戳与 `##[group]` 步骤名称。相邻失败合并为有限长度的上下文窗口，不跨不同步骤合并。每份日志最多记录 24 个窗口；超出时保留最早和最晚的窗口，并明确标记索引不完整。没有可识别标记时仍可查看全文。

这些标记用于定位线索，不是经过验证的根因或失败分类标签。时间戳保留源日志文本，不推断没有记录的时间或步骤。

每条新日志证据包含可选 `log_index`。摘要最多 4,000 个字符，截断时记录 `excerpt_truncated=true`。完整脱敏日志始终保留，空日志的证据行号为 0。历史证据无需迁移，仍可通过新的分页接口读取。

## 模型日志片段

短日志在额度内逐字保留。长日志优先选择高优先级失败窗口，再保留少量开头和结尾；额度不足时记录省略的完整行段与被截断的单行。片段上的“原日志 Lx–Ly”标记使用完整产物的行号，不把节选重新编号成原日志。

| 场景 | 文本上限 |
| --- | --- |
| 未登记 GitHub 仓库的日志诊断 | 10,000 字节 |
| 修复组的目标基线 / 回归基线 | 各 5,000 字节 |
| 固定策略带反馈修正的回归输出 | 6,000 字节 |

上限包含长日志的行号标记，UTF-8 字符不会从中间截断。所有模型、框架和工具调用继续共用原有任务预算；日志选择不增加调用次数或追加额度。

每次选择另归档一个 `log_context` 文本产物：头部为来源产物 ID、SHA256、字节额度、总行数、保留 / 省略范围和截断行号的 JSON，空行后为实际交给模型的日志文本。相关证据卡提供“下载模型使用的日志片段”链接。模型材料的 `log_selection` 指向这份归档；引用的来源产物均属于当前任务。两个基线的范围分别对应各自的日志产物，不使用拼接后无法映射的行号。

原生工具模式的初始日志索引也包含行数与失败窗口，便于调用 `read_ci_log` 定位。工具自身的 100 行 / 10,000 字节读取边界保持原有约束，超长单行仍可能被工具拒绝；浏览器的分段阅读能力不扩大模型工具权限。四组日志解释基线继续使用原先固定、已校验且小于上限的公开归档。

## 页面阅读与 API

在“证据与日志”展开日志上下文，可以跳转失败窗口或指定行号，并通过上一页 / 下一页阅读。执行日志使用相同组件。浏览器每次最多请求 100 行，不一次创建整份长日志的 DOM；完整脱敏文件仍可下载。旧任务没有索引时仍支持按行阅读。

```text
GET /api/v1/tasks/{task_id}/artifacts/{artifact_id}/lines
    ?start_line=1&start_column=0&max_lines=100
```

接口检查任务会话归属和完整产物 SHA256，只接受 `ci_log`、`baseline_log`、`test_log`。每次最多 200 行、16,000 字节源文本；响应中的 JSON 字段及转义有额外开销。页面使用 100 行。越权或跨任务产物返回 404，非法范围 / 类型返回 422，内容指纹损坏返回 409，响应为 `private, no-store`。

超长行以 Unicode 字符列号续读。`lines` 返回原始行号、当前列号、内容和本行是否完整；`next_line` / `next_column` 是下一页的准确位置，读完后两者为 null。调用方应沿用响应游标，不能总将列号重置为 0；空日志返回空数组及空游标。换行符保留在接口内容中，所有分页内容顺序拼接可还原完整脱敏日志。

当前仍使用数据库保存完整产物，分页减少网络与浏览器渲染开销，不代表后端已采用对象存储或流式行索引。日志缓存、有限网络重试、实际远端失败 Run 验收和产物保留期清理仍需继续完善。
