## 故障与数据一致性

以下检查在独立 PostgreSQL 环境执行，关闭了模型凭据，不影响日常数据库：

- 相同幂等键只创建一个任务及一条 outbox，实际领取一次；其他会话读取返回 404，跨来源写入被拒绝，Runner 要求内部鉴权。
- Celery 消费进程停止时任务保持排队；恢复后执行一次。排队期间取消的任务保持取消，不产生执行尝试。
- Redis 停机期间 API 仍将任务及未发布 outbox 提交至 PostgreSQL；恢复后交付一次。
- 注入过期心跳后任务变为 `interrupted`，旧 lease 的写入被拒绝。
- 在 Runner 执行活动期间对真实 Celery Worker 发送 SIGKILL，心跳回收将任务标记为 `interrupted`，并确认旧执行已清理。没有把中断结果改为成功。
- PostgreSQL 停机时任务查询返回失败；重启后连接恢复、任务数量不变。Runner 停机时健康信息报告不可用，重启后恢复。
- 4.0 空指导对照可在 PostgreSQL 预登记 40 个执行槽位，重复请求幂等，会话隔离、取消及离线报告复算通过；未启动这些槽位或声称取得模型成绩。

## 修正与保留状态

发现真实浏览器验收创建的会话文件采用默认权限；已在 live 配置设置 `umask 077`，实际浏览器写出文件的权限检查为 `0600`，已有本地验收会话文件也已收紧权限。业务代码无新增改动。

原验收材料已备份，本轮过程、摘要和日志保留在 Git 忽略目录 `var/qa/deployment-20261029-110700/`。含令牌的状态文件仅本机留存，不应公开上传。临时测试进程和 Compose 服务在验收后停止，测试数据与卷保留；SQLite 主站继续在 `http://127.0.0.1:8000` 运行。

## 验收边界

目前证明的是同一台机器上的部署和恢复。尚未验收公网 HTTPS / 代理、跨主机或账号隔离、多实例与负载运行，以及生产级备份恢复。独立评分服务在隔离验收后停止，日常 `.env` 未改为启用评分。
