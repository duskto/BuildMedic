# 开发集离线对照

当前支持四组公开开发集对照，并保留旧版两组清单和报告。任务清单在执行前登记，包含源码与日志指纹、修复组相同总预算、重复次数和工具开关；运行顺序在执行前循环轮换。暂不支持导入挑选后的历史成功任务、经验累积、隐藏标签或自称 held-out 测试集。

登记清单不请求模型。页面“策略对比”可登记三个案例、核对设置，再点击“运行 / 继续对照”。页面按顺序安排任务，当前项结束后归档再启动下一项。刷新或关闭页面会停止安排后续项，已提交任务继续；返回后可继续运行。命令行适合持续运行和恢复：

```sh
uv run --extra adaptive python scripts/dev.py
# 另一终端；会产生真实模型用量
uv run --extra adaptive python scripts/run_evaluation.py \
  --plan evaluation/four-arm.json \
  --state var/acceptance/four-arm-session.json
```

四组清单 `schema_version=2.0` 包含三个开发案例 × 四组，共 12 项。修复组每项最多 12 次调用、100,000 Token、600 秒，所有尝试、候选和策略提议共用本组任务预算，不为每次尝试重置额度。可重复 1–3 次，独立多尝试可设置 2–4 次（默认 4），工具循环为三个修复组同时开关。经验库固定关闭。

| 组别 | 执行规则 |
| --- | --- |
| A：`logs` 日志解释 | 仅读取固定的本地 Docker 历史目标日志，不读取源码或调用 Runner；最多 2 次模型请求（含格式修正），Token 上限取修复预算与 100,000 的较小值；不能交付补丁或声称根因已通过源码验证 |
| B：`standard` 单次固定策略 | 一次独立诊断；候选仍做目标 / 回归与最终独立验证，不进行带反馈的第二次补丁修正 |
| C：`multi` 独立多次固定策略 | 每次使用相同初始材料和策略，不共享之前的补丁、测试反馈或模型对话；完成全部预登记尝试后，选择首个通过公开候选检查的补丁，再另做独立验证 |
| D：`adaptive` Harness² | 原有 k=1、4 个 rollout 和 3 次策略提议；最终组合结果仍独立验收 |

日志组是诊断基线，不能与 B/C/D 的公开修复通过数比较。没有诊断私有评分标准时，`diagnosis_accuracy` 始终为 null；页面只显示诊断交付数。日志组在 Runner 停止时也可以完成。跨尝试的初始材料 hash、候选、模型与工具记录均可审阅。预算耗尽或取消会立即停止，不在停止后为先前候选补做验收。

公开日志位于 `evaluation/public_logs/*.json`，来自此前真实 Docker 目标检查，包含来源、镜像与源码指纹；它们不是 GitHub Actions 运行记录，也不是隐藏评分材料。清单登记时及执行前核对日志与源码，内容变化会拒绝继续。

旧版 `schema_version=1.0` 清单仍见 `evaluation/development.json`，保持三个案例 × 两组、共 6 项。其标准策略最多两次带反馈修正，不等同于新版 B 组单次策略。已有报告、幂等键和 hash 复算口径保留；新字段仅加入新版报告。

CLI 的状态文件包含私有会话 cookie，权限为 0600，应留在被忽略的 `var/`。中断等待后使用相同命令恢复，不重复创建任务；不得改用新的状态文件后声称接续原实验。`--cancel` 停止安排后续项，并请求取消当前项。API / Worker / Runner 仍需运行；CLI 不替代队列执行器。浏览器用相同会话才能查看 CLI 创建的记录。

模型 ID、提供方、端点 hash、思考开关、输出上限、平台调用上限、Runner 配置、框架 SHA 和实现 / 基础策略指纹在登记时冻结。推进新任务及每次模型调用前检查配置变化；漂移时停止，不替换实验输入。框架 seed 不等于服务商输出可重复。每个任务仍走现有 outbox、并发额度、租约、取消和独立 Runner 检查。

## 指标口径

| 字段 | 含义 |
| --- | --- |
| `planned` | 预先登记的该组总任务数，包含失败、中断和未运行项 |
| `finished` | 已冻结终态输入的任务数；进行中结果仅为暂时统计 |
| `public_verified` | 原失败复现，且选中补丁通过不同执行 ID 的最终公开目标 / 回归检查 |
| `reproduced` | 原失败已复现的任务数 |
| `calls` / `tokens` | 全部角色和格式修正请求的实际调用数 / 已知 Token |
| `unknown_usage` | 用量不完整的任务数，已知 Token 不能冒充完整总量 |
| `wall_seconds` | 各任务执行墙钟耗时总和，不包含队列等待和实验暂停 |
| `checks` / `rollouts` | 实际检查次数和 rollout 数，包含失败的执行 |
| `cost_usd` | 全部已归档任务有可靠费用时才求和，否则为 null |
| `tokens_per_public_verified` | 所有用量完整时，总 Token / 公开通过数；零通过时 null |
| `cost_per_public_verified` | 总费用 / 公开通过数；费用未知或零通过时 null |

这里的公开通过数不是独立隐藏行为修复率。`hidden_verified` 保持 null，没有填造诊断准确率、误报修复率或新增隐藏回归率。相同上限不代表两组实际消耗相同；应同时看成功数、调用和 Token。重复次数不足时不能报告稳定收益。

结束时优先冻结平台结束报告及其 hash；排队即取消的任务可冻结终态快照。重新验证或后续任务字段变化不改写冻结输入。服务端基于冻结输入重算统计，检查独立执行、补丁、原始测试身份与环境指纹，不只读取 `outcome=repaired`。逐项记录保留任务链接、框架 / 策略 / 模型信息、报告来源及归档指纹。

下载的报告和 CLI 的 `*-report.json` 包含冻结输入，可断网复算，不请求模型或 GitHub：

```sh
uv run --extra adaptive python scripts/recompute_evaluation.py \
  var/acceptance/four-arm-session-report.json
```

复算校验输入、清单和配置指纹，再重建逐项结果与全部汇总；不一致时失败。报告包含任务证据，应沿用原会话的数据保管范围；hash 用于完整性检查，不是数字签名。

## API 与权限

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| POST | `/api/v1/experiments` | 幂等登记清单，需 Idempotency-Key；不执行模型 |
| GET | `/api/v1/experiments` | 当前会话列表及分页 |
| GET | `/api/v1/experiments/{id}` | 逐项结果与重新计算的统计 |
| POST | `/api/v1/experiments/{id}/advance` | 返回在途任务，或原子创建下一项及 outbox；全部结束后完成归档 |
| POST | `/api/v1/experiments/{id}/cancel` | 停止后续项并取消当前项，可重复重试清理 |
| GET | `/api/v1/experiments/{id}/report` | 下载报告 |

`GET /api/v1/evaluation/cases` 提供三个可登记案例的源码与日志指纹。所有操作检查会话归属，越权返回 404。客户端不能提交指标、任意任务 ID、脚本、模型设置或私有评测路径。每会话最多 50 个清单；四组清单最多 36 项执行，旧版两组最多 18 项。数据库迁移 `0003` 增加评测表，本次扩展仅使用原有 JSON 内容，不新增迁移。四组任务不能绕过清单关联重试，重复实验应新建完整清单。
